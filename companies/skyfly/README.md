# SkyFly

Airline (booking and check-in). Customers search flights, book and check in online. Travel agencies pull bookings through a partner API with an API key.

|---|---|
| Language | node (`companies/runtime/node`) |

| Public entry | `api.skyfly.example`, TLS |

| OpenAPI | 3.0.3 at `/api-docs` |
| Outside APIs | gds-provider |

## Planted weaknesses (7)

| # | ATG rule | Where | What was planted |
|---|---|---|---|
| 1 | TS-02 | `api-gateway` (/api/checkin) | The check-in route has no TokenRelay filter: the gateway lets anyone through. |
| 2 | TS-01 | `GET /checkin/{booking_id}` | Check-in details, passport number included, for anyone who guesses a booking number. |
| 3 | TS-01 | `POST /checkin/{booking_id}/boarding-pass` | Anyone can issue a boarding pass for any booking number. |
| 4 | API7 | `POST /bookings/{booking_id}/webhooks` | Takes a webhook_url the server will call later. |
| 5 | API10 | `booking-service` (gds-provider) | Seat availability comes from an outside GDS. |
| 6 | API9-ZOMBIE | `GET /partner/v1/fares` | Deprecated v1 still used by agencies. |
| 7 | API4 | `checkin-service` | No CPU or memory limits on a service the internet reaches. |
